# Coffee Pre-Order MVP

Демо-MVP для кофейни с одной общей очередью заказов:
- online-заказы от гостей,
- очные заказы со стойки,
- один общий экран очереди для бариста.

Главная идея проекта: **бариста видит один поток**, а online-заказ попадает в очередь **только после успешной оплаты**. На текущем этапе оплата реализована как **demo payment flow**, без реального банка и без интеграции с кассой кофейни.

## Что сейчас умеет приложение

- customer flow: `/menu` → `/cart` → `/checkout` → `demo payment` → `/order/[id]`
- простая demo-регистрация и вход, чтобы тестировать приложение с нескольких аккаунтов
- единая очередь для online и offline заказов
- offline intake demo screen на `/cashier`
- barista monitor на `/barista`
- daily public order number после успешной online-оплаты или подтверждения очного заказа
- автоматический сдвиг очереди после `Ready`
- отмена online-заказа, пока он в `Waiting`

## Что специально НЕ сделано

- реальный эквайринг
- реальная СБП
- реальная фискализация
- интеграция с POS / KKT / терминалом кофейни
- возвраты и частичные возвраты

Это сознательное решение: сначала сильное демо, потом discovery по инфраструктуре кофейни.

## Маршруты

### Customer

- `/menu` — меню
- `/cart` — корзина
- `/checkout` — checkout перед оплатой
- `/checkout/payment/[paymentId]` — demo payment screen
- `/order/[id]` — статус заказа
- `/orders` — мои заказы
- `/sign-in` — вход
- `/sign-up` — регистрация

### Staff

- `/staff-access` — лёгкий staff-доступ для демо
- `/cashier` — offline order intake demo screen
- `/barista` — shared queue monitor

### API

- `POST /api/auth/sign-up`
- `POST /api/auth/sign-in`
- `POST /api/auth/sign-out`
- `POST /api/orders/offline`
- `GET /api/orders/[id]`
- `POST /api/orders/[id]/cancel`
- `POST /api/payments/demo/start`
- `POST /api/payments/[paymentId]/result`
- `GET /api/queue`
- `POST /api/queue/ready`

## Установка

Нужен `Node.js 20+`.

1. Установите зависимости:

```bash
npm install
```

2. Создайте `.env`:

```bash
cp .env.example .env
```

3. Подготовьте Prisma и базу:

```bash
npm run prisma:generate
npm run db:push
```

4. Заполните базу тестовым меню:

```bash
npm run db:seed
```

## Запуск

Режим разработки:

```bash
npm run dev
```

Production-сборка:

```bash
npm run build
npm run start
```

По умолчанию приложение открывается на [http://localhost:3000](http://localhost:3000). Если порт занят, Next.js выберет следующий свободный.

## Как устроено демо

### 1. Online flow

1. Пользователь регистрируется или входит.
2. Собирает корзину.
3. Переходит в `/checkout`.
4. Открывает `demo payment`.
5. Если результат `Success`, заказ:
   - получает публичный номер,
   - становится подтверждённым,
   - попадает в общую очередь.
6. Если результат `Fail` или `Cancel`, заказ в очередь не попадает.

### 2. Offline flow

`/cashier` сейчас не притворяется реальной кассой.  
Это demo-экран, который показывает: **уже принятый очный заказ тоже можно отправить в общую очередь**.

### 3. Queue flow

- активные статусы очереди: `WAITING` и `PREPARING`
- верхний заказ считается текущим
- после `Ready` следующий заказ автоматически становится текущим

## Ключевые модели

### `User`

Нужен для demo-auth и привязки online-заказов к конкретному пользователю.

### `Session`

Простая cookie-session для входа в демо.

### `Order`

Хранит:
- источник (`ONLINE` / `OFFLINE`)
- статус заказа
- публичный номер
- данные очереди

### `Payment`

Отделён от `Order`.  
Сейчас это demo-платёж, но именно сюда потом можно подключить реальный payment provider.

## Важные архитектурные решения

- `Order` и `Payment` разделены
- `order status` и `payment status` разделены
- online-заказ не попадает в очередь до `payment success`
- `/cashier` позиционируется как `offline intake demo`, а не как замена POS
- текущая кассовая инфраструктура кофейни пока не затрагивается

## Ручная проверка

### Базовый demo flow

1. Откройте `/sign-up` и создайте тестового пользователя.
2. Откройте `/menu`, соберите заказ.
3. Перейдите в `/cart`, затем в `/checkout`.
4. На `/checkout/payment/[paymentId]` нажмите `Success`.
5. Убедитесь, что заказ открылся на `/order/[id]` и получил номер.
6. Откройте `/barista` и проверьте, что заказ появился в общей очереди.

### Проверка offline flow

1. Откройте `/staff-access` и введите код `demo123`.
2. Перейдите на `/cashier`.
3. Добавьте несколько позиций.
4. Нажмите `Добавить очный заказ в очередь`.
5. Проверьте на `/barista`, что очный заказ встал в ту же очередь.

### Проверка multi-account

1. Выйдите из первого аккаунта.
2. Создайте второй аккаунт.
3. Сделайте новый online-заказ.
4. Проверьте, что у каждого пользователя своя корзина, свои заказы и свой доступ к `/order/[id]`.
